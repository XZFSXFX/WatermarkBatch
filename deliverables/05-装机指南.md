## 一、装机形态（个人自用，不经任何商店）

本项目不经过任何应用商店，构建产物只装到自己（或家人）的 iPhone 上。因此这里的"发布"只有四件事：

① **装得上**（签名有效）；② **用得住**（7 天/1 年内不失效，失效后 5 分钟内可恢复）；③ **丢不了**（模板与导出记录不因重签丢失）；④ **可回退**（上一稳定版 .ipa 随时可重装）。

**装机流水线（本机最短路径）**：

```
质量门禁通过（04 §六）
  → 定版本号 X.Y.Z + build 号
  → Xcode Archive（Release 配置）
  → 导出 .ipa（方案B：Ad Hoc；方案A：Development 导出或直装）
  → 安装到 iPhone（Xcode 直装 / Windows 端 Sideloadly / AltStore）
  → 10 分钟真机冒烟（04 §1.3 冒烟标准）
  → 归档 releases/vX.Y.Z/
```

**与前序方案的衔接**：
- 分发方式已裁决为**仅个人自用侧载**，因此 01 中关于商店分发节奏的假设不再作为因素；
- 02 的业务指标（下载量/评分）不再适用；本地匿名统计仅用于自用排障，App 零网络请求不变；
- 03 §7 Info.plist 权限文案四键**完全保留**——系统权限弹窗与本项目是否上商店无关，文案仍须与 PRD 第七章逐字一致；
- 04 §六门禁第 9 项改为"重装后权限弹窗文案核对"（并入第八章清单）。

## 三、签名方案（二选一，各给完整步骤）

### 3.0 决策对比

| 维度 | 方案 A：免费 Apple ID 个人签名 | 方案 B：付费个人开发者账号 |
|------|------|------|
| 成本 | 0 元 | $99/年（约 ¥688/年） |
| 签名有效期 | **7 天**（过期 App 打不开，重签即可） | **1 年**（以描述文件为准） |
| 安装设备 | 仅限自己信任的设备 | 注册过 UDID 的设备（上限 100 台/年，本项目只注册自己的） |
| 维护负担 | 每周 1 次刷新（AltStore 可自动化为"无感"） | 每年 1 次重导出 |
| 可用 Capability | 基本无（无 iCloud/推送/App Group） | 有，但本项目用不到 |
| .ipa 导出 | Development 导出（部分 Xcode 版本对 Personal Team 限开放，不可用则走直装/重签路径） | Ad Hoc 导出（完整支持，推荐） |
| 适用阶段 | 验证期 / 不想花钱 / 接受每周折腾 | 长期自用（推荐终态） |

**与项目的匹配说明**：本 App 纯本地零网络，Info.plist 仅四键（03 §7），**不申请任何 Capability/entitlement**——免费签名"无付费能力"的限制对本项目**零影响**，这是纯本地架构带来的发布红利。

**建议**：开发验证期直接用方案 A（免费）；确定长期自用后升级方案 B，一年只维护一次，且归档的 .ipa 可随时重装。

### 3.1 方案 A：免费 Apple ID 个人签名（7 天有效）—— Mac + Xcode 路径

**前置**：任意 Apple ID（免费注册即可）、Mac + Xcode 16、USB 数据线、自己的 iPhone。

1. **登录 Apple ID**：Xcode → Settings → Accounts → "+" → 登录 → 该账号自动出现在 **Personal Team**（个人团队）下。
2. **配置签名**：打开 WatermarkBatch 工程 → TARGETS → Signing & Capabilities：
   - Team 选 **Personal Team**；
   - 勾选 **Automatically manage signing**；
   - Bundle Identifier 填 **com.local.watermark**（个人自用可随意起名，规则与纪律见第五章；首次会注册 App ID，Xcode 自动完成）；
   - **不添加任何 Capability**（保持无 entitlements）。
3. **首次安装**：iPhone 解锁、USB 连 Mac、"信任此电脑" → Xcode 顶部设备栏选你的 iPhone → **Cmd+R** → Xcode 自动生成 7 天有效的个人描述文件并安装 App。
4. **信任开发者**：首次打开 App 前在 iPhone 上操作：设置 → 通用 → **VPN与设备管理** → "开发者App"下你的 Apple ID → 点"信任"。
5. **正常使用**：7 天内与普通 App 无差别（相册读写、批量后台任务全部可用）。
6. **7 天到期后**：App 图标仍在，点击提示"无法验证"/直接闪退——**这是正常现象，不是故障**。回到 Mac 连上 iPhone 再按一次 Cmd+R（覆盖安装）即可恢复，模板与导出记录不丢（原理见第六章）。身边无 Mac 时用 Windows 端 Sideloadly 重签（第四章）。

**免费账号三条硬限制**：
- 每台设备**同时最多 3 个**自签 App（装第 4 个须先删一个）；
- 每 7 天**最多注册 10 个 App ID**（Bundle ID 反复大改会烧配额——定一个名字别动）；
- 签名仅对**登录该 Apple ID 并信任的设备**有效。

### 3.2 方案 B：付费个人开发者账号（1 年有效）

**前置**：在 developer.apple.com 购买 Apple Developer Program 个人会员（$99/年），激活后同一 Apple ID 登录 Xcode。

**路径 B1：日常直装（开发签名，最简单）**
1. Xcode → Settings → Accounts 登录付费账号；
2. Signing & Capabilities → Team 选个人开发者 Team（不再是 Personal Team）→ 自动管理签名；
3. Cmd+R 直装 iPhone。开发签名**同样 1 年有效**，日常开发与自用这条路径最省事。

**路径 B2：Ad Hoc 导出（推荐："一次构建、长期安装、可随时重装"）**
1. **注册设备 UDID**：iPhone 连 Mac → Devices and Simulators 窗口右键设备 → "Add to Additional Devices…"；或 Windows 端用爱思助手/3uTools 读取 UDID，到 developer.apple.com → Devices 手动添加；
2. **Archive**：见第七章（Release 配置）；
3. **导出**：Organizer → 选中 Archive → Distribute App → Custom → **Ad Hoc Distribution** → 勾选包含你设备的目标 profile → Export 生成 `.ipa`（自带 1 年有效签名）；
4. **安装**：Mac 端用 Devices 窗口或 Apple Configurator 2 拖入安装；Windows 端用 Sideloadly（证书方式或 Apple ID 方式均可）/ 爱思助手 / iMazing 拖入安装；iPhone 装有 AltStore 时，可在"文件"App 中把 .ipa 分享给 AltStore 安装；
5. **一年到期**：续费账号 → 重新 Archive 导出 → 覆盖安装，数据不丢。


**证书注意事项**（通用手册"证书签名常见坑"的个人版）：
- 证书与描述文件有效期：开发证书 1 年、分发证书 3 年、**描述文件 1 年——以描述文件为准**，到期重新导出覆盖安装即可；
- 描述文件与 Bundle ID 必须匹配（Xcode 自动管理签名下基本不会出错）；
- 付费账号在 Windows 端重签：Sideloadly 高级选项支持导入 `.p12` 证书 + `.mobileprovision` 描述文件直接签名，无需 Apple ID 登录。

## 四、Windows + .ipa：Sideloadly / AltStore 重签名安装

**场景说明**：本项目编译必须依赖 Mac + Xcode 16（03/04 环境声明）。Windows 场景指：`.ipa` 由 Mac 产出后（自己的 Mac、借用/云 Mac 一次性构建均可），后续的**签名与安装维护在 Windows 上完成**——包括免费账号每周重签、付费账号随时重装。

### 4.1 Sideloadly（推荐：简单直接，免费/付费账号均可用）

**前置**：Windows 10/11、iTunes（Apple 官网桌面版或 Microsoft Store 版，用于设备驱动）、USB 数据线。

1. 下载安装 Sideloadly（官网 sideloadly.io，Windows 版）；
2. iPhone 解锁 → USB 连 Windows → 弹窗"信任此电脑"；
3. 打开 Sideloadly → 把 `.ipa` 拖入窗口 → Apple ID 栏登录：
   - 免费 Apple ID：自动申请 7 天个人描述文件并完成重签；
   - 付费开发者账号：装出 1 年有效 App；也可在 Advanced 选项改用 `.p12 + .mobileprovision` 证书文件签名；
4. （可选）Advanced → Bundle Identifier 可改包名（如 com.local.watermark，注意第五章纪律）；
5. 点 **Start** → 等待安装完成；
6. iPhone：设置 → 通用 → VPN与设备管理 → 信任对应开发者证书；
7. **免费账号每周维护**：到期后重复第 3~5 步（同 Bundle ID 覆盖安装，数据保留，全程约 2 分钟）。

**常见报错速查**：

| 报错/现象 | 处理 |
|---|---|
| 提示需要 App 专用密码 | 账号开了两步验证：appleid.apple.com → 登录与安全 → 生成 App 专用密码，用该密码登录 |
| 安装第 4 个自签 App 失败 | 免费 3 App 上限：先删一个不用的再装 |
| 装完点开闪退 | 未信任证书（第 6 步）或签名已过期（重签） |
| 找不到设备 | 换原装数据线/USB 口，确认 iTunes 能识别设备 |

### 4.2 AltStore（推荐用于"免每周手动刷新"）

**前置**：Windows + 从 **Apple 官网下载桌面版 iTunes 和 iCloud**（⚠️ 不要用 Microsoft Store 版，AltServer 依赖其中的服务组件）。

1. Windows 安装 **AltServer**（altstore.io）；
2. iPhone USB 连接 → 托盘 AltServer 图标 → Install AltStore → 选你的 iPhone → 登录 Apple ID；
3. iPhone 上打开 AltStore（⚠️ AltStore 本身占用免费 3 App 限额之 1）；
4. 侧载水印工坊：在"文件"App 中找到 `.ipa` → 分享 → 用 AltStore 打开 → 安装；
5. **核心价值——自动刷新**：iPhone 与 Windows 处于同一 Wi-Fi 且 AltServer 后台运行时，AltStore 会在后台自动续签，7 天有效期"无感"维持（建议 AltServer 设为开机自启）；
6. 免费/付费账号均支持；付费账号下侧载的 App 有效期 1 年，基本告别维护。

### 4.3 选择建议

| 场景 | 推荐 |
|---|---|
| 只有一台 Windows，能接受每周插一次线 | Sideloadly |
| Windows 长期开机，想让免费签名自动续命 | AltStore |
| 手边有 Mac | 直接 Xcode Cmd+R，最省事 |

## 五、Bundle ID：可随意改，但定下后不要改

1. **可随意改**：个人自用私有包，无商标冲突、无商店账号约束——`com.local.watermark`、`com.watermarkbatch`、`com.你自己的名字.batchmark` 均合法。03 方案默认 `com.watermarkbatch`（BGTask ID 同源），个人自用推荐 `com.local.watermark` 以示私有包。
2. **权限文案不需要重配**：`NSPhotoLibraryUsageDescription` 等四个 Info.plist 键是**打包进 App 的静态文案，与 Bundle ID 零耦合**——改 Bundle ID 后文案原样生效，无需任何重新配置。
3. **但系统会视为"新 App"**：换 Bundle ID 安装后，iOS 视为全新应用 → 相册权限**重新弹窗授权**、沙盒数据为空（旧 App 数据不可见）。
4. **联动修改项（仅 1 处，建议性）**：`BGTaskSchedulerPermittedIdentifiers`（03 §7 的 `com.watermarkbatch.export`）建议同步改为 `com.local.watermark.export` 保持命名一致——该键与 Bundle ID 无强绑定，但一致可避免后续维护混淆；改后 App 首次启动会重新注册后台任务。
5. **纪律**：一旦产生真实使用数据（模板/导出记录），**不要再改 Bundle ID**（数据不迁移，见第六章）；免费账号每周 10 个 App ID 配额也要求包名稳定。

## 六、签名过期与数据安全（个人发布的核心承诺）

### 6.1 过期表现与恢复

| 方案 | 到期表现 | 恢复动作 | 数据 |
|---|---|---|---|
| 免费 7 天 | 图标在，点击提示"无法验证"/闪退——**正常现象，非故障** | 任一方式重签覆盖安装（Xcode Cmd+R / Sideloadly 重签 / AltStore 自动或手动刷新），约 2~5 分钟 | **不丢** |
| 付费 1 年 | 同上 | 续费 + 重新导出 .ipa 覆盖安装 | **不丢** |

**关键原则：重签 = 覆盖安装，绝对不要先删 App 再装**——删除 App 会同时清空沙盒容器（数据全丢）。

### 6.2 数据不丢的技术依据（衔接 03 技术方案）

- **一级保证（存储位置）**：03 §一持久化选型——水印模板（`WatermarkTemplateStore`）与导出记录（`ExportRecordStore`）以 JSON 落盘 **App 沙盒 `Documents/` 目录** + UserDefaults 辅助，**不放 tmp/、不放 Caches**（后两者系统可随时清理，Documents 永不清理）；
- **二级保证（安装机制）**：iOS 对同 Bundle ID 的覆盖安装（无论签名证书是否更换）**保留沙盒容器**，只替换 App 二进制；
- **三级兜底（备份）**：Documents 默认**随整机 iCloud 备份/电脑备份**（03 §六已声明）——即使手机丢失/抹机，恢复备份后数据可回。

注：App 未声明文件共享键（UIFileSharingEnabled），Documents 不在"文件"App 中可见，属正常设计；备份依赖整机备份而非文件级导出。

### 6.3 真正会丢数据的四种情况（务必避开）

| 情况 | 后果 | 规避 |
|---|---|---|
| **先删除 App 再重装**（重签时手滑删了图标） | 沙盒清空，模板/记录全丢 | 重签永远走覆盖安装 |
| 更换 Bundle ID | 视为新 App，旧数据不可见 | 定名后不改（第五章） |
| 抹掉所有内容与设置 / 换新机不恢复备份 | 容器消失/不迁移 | 保持 iCloud 整机备份开启 |
| 删除 App 时勾选"从 iCloud 备份中移除" | 兜底也没了 | 删除弹窗永远不选该选项 |

说明：相册素材本身存于系统相册（随 iCloud 照片同步），不受 App 沙盒影响——即使上述最坏情况发生，丢的只是模板与导出记录，**已导出到相册的成品图/视频不会丢**。

## 七、本机 Xcode Archive + 导出 .ipa 最短路径（无 CI/CD）

**明确声明：本项目不建设任何 CI/CD**（Xcode Cloud / GitHub Actions / 云流水线均不需要）——无服务器、无环境矩阵、无团队协作，本机一条路径即全部。

| Step | 操作 | 要点 |
|---|---|---|
| 0 前置 | Mac + Xcode 16 + iPhone + 签名账号（第三章 A 或 B） | 质量门禁已通过（第二章） |
| 1 版本号 | TARGETS → General：`Version（MARKETING_VERSION）= X.Y.Z`；`Build（CURRENT_PROJECT_VERSION）` 递增 | 规范见下；若用 git，打 tag `vX.Y.Z` |
| 2 Release 预验 | Scheme → Edit Scheme → Run 改为 **Release 配置**，真机跑一遍 10 分钟冒烟 | 避免只有 Debug 验证过的包被 Archive |
| 3 Archive | Product → **Archive**（自动使用 Release 配置） | 04 §1.3 冒烟 + 上线前回归集通过后再执行 |
| 4 导出 | Organizer → 选 Archive → **Distribute App** | **方案 A**：Custom → Development 导出（若你的 Xcode 版本对 Personal Team 未开放该入口，则免导出——日常维护就是 Mac 直装或 Sideloadly 重签）；**方案 B**：Custom → **Ad Hoc** 导出（勾选含你设备的 profile） |
| 5 传输安装 | Mac 直装（Devices 窗口拖入）；或拷到 Windows 走第四章；或 iPhone 装有 AltStore 时在"文件"App 分享给 AltStore 安装 | 传输用 U 盘/网盘/AirDrop 均可（.ipa 只是文件） |
| 6 冒烟 | 安装后 10 分钟核心闭环：选 10 张混合素材 → 加水印 → 批量导出 → 记录可见；权限弹窗文案与 PRD 第七章逐字核对 | 04 §1.3 冒烟标准 |
| 7 归档 | `.ipa` + 版本记录存 `releases/vX.Y.Z/`（第九章） | 上一稳定版必留（回退用） |

**版本号规范（个人版）**：`主.次.修订`——首次 1.0.0；功能性更新升次版（1.1.0）；修缺陷升修订（1.0.1）。每次发布一条版本记录（日期/版本/变更一行摘要/产物位置），发布完成 24 小时内归档（对齐通用手册归档纪律）。

## 八、装机检查清单（逐项打勾后放行）

- [ ] 质量门禁九项全过（04 §六）：P0=0、9 条自测清单 100%、六项性能 100%、崩溃 0
- [ ] 上线前回归集（≤30 分钟）执行通过

## 九、版本管理与回退

**回退方案**（通用手册回滚模板的个人版）：

```
回退触发条件：新版本出现 P0 缺陷（格式降级类）或影响核心闭环的阻断问题
回退步骤：
  1. 取 releases/ 下上一稳定版 .ipa
  2. 覆盖安装到 iPhone（Xcode Devices 拖入 / Sideloadly / AltStore），约 5 分钟
  3. 10 分钟冒烟 + 模板列表完整性抽查
数据兼容纪律（保证回退后模板/记录不废）：
  本地数据模型（WatermarkConfig / WatermarkTemplate / ExportRecord，均为 Codable JSON）
  字段只增不删、不改语义——旧版 App 必须能读新版落盘的数据；违反此纪律的版本禁止发布
```

**归档结构**：

```
releases/
├── v1.0.0/
│   ├── BatchMark-1.0.0.ipa          ← 本次制品
│   └── RELEASE.md                   ← 版本记录：日期/版本/变更摘要/git commit/签名方案/回归集结果
└── v1.0.1/
    └── ...
```

- 纪律：至少保留**上一稳定版**制品随时可装；版本记录在发布完成 24 小时内写入，缺陷记录并入 RELEASE.md。
