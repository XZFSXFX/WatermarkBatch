# iOS 批量水印 App · 技术研发方案

> 版本：v1.1 ｜ 角色：全栈研发师（eng） ｜ 上游：用户原始需求（相册照片/Live Photo/动图/视频批量加水印，不缩图、不压缩、格式原样保留）
> **环境声明：当前交付环境为 Windows（无 Xcode），本方案所有 Swift 代码均未经编译验证，需在 Mac + Xcode 16（iOS 17+ SDK）完成首次编译与全部性能验收。**
>
> **【v1.2 契约修订（内存红线）】** 新增 `ProcessedOutput.imageFile(url:uti:)`：大于 256KB 的图片产物由 BatchQueue 落 tmp 后以 URL 形态持有，`stillImage(data:)` / `animatedImage(data:)` 仅用于小图。原因：100 张 12MP HEIC（q1.0 约 3-5MB）全量驻留内存 ≈300-500MB，直接击穿 <200MB 红线；落盘后内存只保留在飞 2 个任务。导出层对 `imageFile` 走 `addResource(with: .photo, fileURL:)`，与原 data 路径等价；清理时机不变。
>
> **【v1.2 用户显式选项】** `settings.outputLosslessPNG`（默认关）：源为 HEIC/HEIF 的静态照片在开启时输出 PNG 无损，代价是容器改变、体积显著增大（12MP 约 25-35MB）、PNG 对完整 EXIF/GPS/镜头信息的承载能力弱于 HEIC——这是用户需求第十二节明确要求的「自行取舍」项，UI 必须写明代价；Live Photo 静帧与 RAW 不走此路径。
>
> **【v1.1 默认参数锁定（最高裁决，覆盖本文早期章节）】** 依用户需求第十二节「画质优先，宁慢勿损」：
> - 默认（画质优先档）并发 = **2（照片）/ 1（视频）**，同一时刻最多一个视频在编码；内存峰值目标 <200MB，超限降并发不降画质。
> - 视频目标码率 = max(原码率 × **1.3**, 平台推荐值)；音频 passthrough；GOP 与原文件相近；`shouldOptimizeForNetworkUse = false`。
> - JPEG/HEIC 质量 = 1.0，PNG 无损保 alpha；一律不缩放像素尺寸。
> - 唯一降级开关「优先速度」（默认关）：开启后允许视频码率系数 1.0、并发提至 3-4（内存自适应）、JPEG 质量 0.95；切换时弹窗明示「会牺牲部分画质」。
> - 性能验收双口径：第六节硬指标（30 张 ≤8s 等）为「优先速度」档目标值；**默认保守档如实实测**（预期 30 张 10-12s / 1080p30 30-40s / 4K30 60-80s），实测达不到就写实测值，禁止改目标值「达标」。

## 一、技术选型总览（零第三方依赖）

| 层次 | 选型 | 一句话理由 |
|------|------|-----------|
| 语言/并发 | Swift 6（strict concurrency） | 需求硬约束；Sendable 编译期隔离保证批处理队列线程安全 |
| UI | SwiftUI（iOS 17+，深色优先中文） | 四页签结构简单，声明式适合进度流 UI；NavigationStack 分页 |
| 相册访问 | PhotoKit（PHPAsset/PHCachingImageManager/PHAssetCreationRequest） | 唯一能读写系统相册并支持 Live Photo 配对写入的系统框架 |
| 图片合成 | Core Image + Metal（CIContext 共享单例） | GPU 渲染，30×4000×3000 ≤8s 的唯一可行路径，禁 CPU 逐像素 |
| 图像编解码 | ImageIO（CGImageSource / CGImageDestination） | 唯一能逐帧读 GIF/WebP 且透传 EXIF 属性字典的 API |
| 视频读写 | AVAssetReader + AVAssetWriter（VideoToolbox 硬编） | 码率/profile/HDR 元数据精确可控（详见 AB 对比） |
| 视频预览 | AVPlayer + AVVideoComposition | 时间轴实时渲染水印所见即所得 |
| 缩略图 | AVAssetImageGenerator（异步+缓存） + PHCachingImageManager | 相册列表与时间轴胶片条 |
| 后台续跑 | BGTaskScheduler（BGProcessingTask） | 系统唯一官方长任务机制 |
| 持久化 | UserDefaults + Documents 目录 JSON（模板/导出记录） | 数据量极小（<1MB），不引入数据库，符合反过度设计原则 |
| 网络/云端 | 无 | 需求明确纯本地不联网 |

**架构模式判据**：本机工具型 App，天然"单机单体"，按层分包（Models / PhotoLibrary / Rendering / Processing / Export / UI），无服务、无依赖注入容器、无响应式框架——复杂度与 MVP 规模严格匹配。

## 二、AB 选型对比（逐项打分，10 分制）

### 2.1 视频水印导出管线

| 维度 | A：AVVideoComposition + AVAssetExportSession | B：AVAssetReader + AVAssetWriter 手动管线 | 结论 |
|------|------|------|------|
| 画质可控性 | **6**：仅能用预设（Highest/ProRes 等），无法显式设定码率公式 max(原×1.3, 平台推荐)、无法保证 profile/level ≥ 原文件 | **9**：AVAssetWriterInput.outputSettings 显式指定 codec/profile/level/平均码率/色彩属性，完全按需求参数化 | B 胜 |
| 性能 | **6**：导出会话内部管线不透明，AVMutableVideoComposition+Core Animation Tool 强制走 SDR 中间层，4K 实测常超预算 | **9**：CVPixelBuffer 直通硬编（VideoToolbox），帧级 autoreleasepool 控内存，1min 4K30 ≤60s 可达 | B 胜 |
| HDR 保真 | **5**：AVVideoCompositionCoreAnimationTool 会将 HDR tone map 到 SDR；10bit HEVC/HLG/Dolby Vision 经合成层后位深与传递函数易被破坏（已知系统行为） | **9**：从源 track 的 formatDescription 逐项复制 colorPrimary/transferFunction/matrix（HLG/PQ/BT.2020），HEVC Main10 写回，禁 tone map | B 胜 |
| 失败面 | 预设对齐不齐，异构文件（旋转元数据、多变音轨）黑盒 | 需自处理旋转（preferredTransform 合成进 pixel buffer）与音轨类型检测 | — |

**结论：选 B。** A 仅作为 B 在个别疑难文件（如交错视频）上抛错时的降级提示路径（提示用户改用单独处理），不做双管线维护。

### 2.2 视频预览方案

| 维度 | A：AVPlayer + AVVideoComposition（自定义 compositor） | B：AVAssetImageGenerator 抽帧渲染 |
|------|------|------|
| 实时性 | **9**：播放/拖动均为实时合成，30/60fps 满帧，水印时间段显隐由 compositor 按 frame 时间判断 | **5**：requestedTimeTolerance 会跳关键帧，拖动不连续，无音频 |
| 性能/内存 | **8**：GPU 合成，AVPlayer 管理缓冲 | **5**：seek 代价高（关键帧距离），4K 抽帧内存尖峰 |
| 适用性 | 完整预览（播放+时间轴拖动+水印显隐） | 仅适合时间轴胶片条静态缩略图（异步生成后缓存复用） |

**结论：预览主体用 A；B 只用于时间轴下方缩略图胶片条（`generateCGImagesAsynchronously` + NSCache），两者不混用。**

## 三、系统分层架构

```
┌─────────────────────────── UI 层（SwiftUI，块C）───────────────────────────┐
│  相册选择页 │ 水印编辑页 │ 预览(照片/视频/Live/GIF) │ 批量任务页 │ 导出记录页   │
└──────┬──────────────────────────────────────────────────────────────────┘
       │ 依赖（单向，禁止反向/循环）
┌──────▼───────────── 队列调度层（块B）───────────────┐
│  BatchQueue：默认并发 2照片/1视频；「优先速度」档 3-4(内存自适应) │
│  AsyncStream<BatchProgress> → UI 实时进度             │
└──────┬──────────────────────────────────────────────┘
       │
┌──────▼───────── Rendering 层（块A）──────────────────┐   ┌──────────────┐
│  WatermarkCompositor（单例，共享 CIContext+Metal）     │   │ Watermark    │
│  ├─ PhotoProcessor   (照片/RAW→HEIC 告知)             │◄──│ 模型层(块A)   │
│  ├─ LivePhotoProcessor(still+MOV 拆解/重配对)         │   │ 文字/图片配置  │
│  ├─ AnimatedProcessor(GIF/WebP 逐帧)                  │   │ placement     │
│  └─ VideoProcessor   (Reader→合成→Writer硬编,音频直通) │   │ tiling/模板   │
└──────┬──────────────────────────────────────────────┘   └──────────────┘
       │
┌──────▼───────────── PhotoLibrary 层（块A）────────────┐
│  PhotoLibraryService：权限/取数/日期分组/缓存           │
│  iCloud 原图下载(进度+重试)  AlbumWriter  ExportService │
│        (performChanges 批量写入 / Live 配对 / 相簿)    │
└─────────────────────────── PhotoKit / 系统相册 ─────────┘
```

**核心链路**：UI 选择 → PhotoLibraryService 取原图（iCloud 下载带进度）→ AssetProcessor 调 WatermarkCompositor 单帧合成 → ProcessedOutput → ExportService 一次 performChanges 写回（保留创建时间/文件名）。预览与导出共用 `compositedFrame` 同一入口，从机制上保证所见即所得。

## 四、【接口契约】（块C 的 UI 工程师与块B 并行开发，直接按此调用；签名以本节为准，不得含糊）

> 全部代码 **需在 Mac+Xcode 16 编译验证**；并发标注按 Swift 6 strict concurrency 书写。

```swift
// MARK: - Models/WatermarkModels.swift（块A）
enum MediaKind: String, Codable, Sendable, CaseIterable {
    case photo, livePhoto, animated, video, raw
}

struct WatermarkTextConfig: Codable, Sendable, Equatable {
    var text: String
    var fontName: String            // 系统 PostScript 名，如 "PingFangSC-Semibold"
    var fontSizePt: CGFloat
    var colorHex: String            // "#RRGGBB" 或 "#RRGGBBAA"
    var strokeEnabled: Bool
    var strokeColorHex: String
    var strokeWidthPt: CGFloat
    var shadowEnabled: Bool
    var shadowColorHex: String
    var shadowOffsetPt: CGSize      // pt 单位偏移
    var shadowBlurRadiusPt: CGFloat
    var opacity: CGFloat           // 0...1
    var letterSpacingPt: CGFloat   // 正值放大，负值缩小
}

struct ImageWatermark: Codable, Sendable, Equatable {
    var pngData: Data               // 透明 Logo，保留 alpha
    var pixelSize: CGSize           // 原始像素尺寸
}

enum WatermarkContent: Codable, Sendable, Equatable {
    case text(WatermarkTextConfig)
    case image(ImageWatermark)
}

struct WatermarkPlacement: Codable, Sendable, Equatable {
    var centerXNormalized: CGFloat // 相对输出像素，0...1
    var centerYNormalized: CGFloat
    var scaleNormalized: CGFloat    // 水印层长边 / 输出短边
    var rotationDegrees: CGFloat    // -360...360
}

struct TilingConfig: Codable, Sendable, Equatable {
    var isEnabled: Bool             // 默认 false（平铺模式默认关闭）
    var spacingNormalized: CGFloat  // 相邻水印间距 / 水印长边，默认 0.5
    var rotationDegrees: CGFloat    // 平铺整体倾角，默认 -30
}

struct WatermarkConfig: Codable, Sendable, Equatable {
    var content: WatermarkContent
    var placement: WatermarkPlacement
    var tiling: TilingConfig
    var safeMarginNormalized: CGFloat // 安全区吸附阈值，默认 0.03
    var timeRange: ClosedRange<Double>? // 视频显示时间段秒；nil = 全程
}

struct WatermarkTemplate: Codable, Identifiable, Sendable, Equatable {
    var id: UUID
    var name: String
    var config: WatermarkConfig
    var createdAt: Date
}

// MARK: - Models/LibraryModels.swift（块A）
enum PhotoAccessLevel: Sendable, Equatable { case full, addOnly, denied }

struct LibraryAsset: Identifiable, Hashable, Sendable {
    let id: UUID                       // App 内部 ID（模板/任务引用它）
    let assetIdentifier: String        // PHAsset.localIdentifier
    let kind: MediaKind
    let pixelSize: CGSize
    let duration: TimeInterval?        // 视频/Live Photo 有效
    let creationDate: Date?
    let originalFilename: String?
    let isInICloud: Bool
}

struct AssetDayGroup: Identifiable, Sendable {   // 日期倒序分组
    let id: Date                                 // 当天 0 点
    let assets: [LibraryAsset]
}

enum TaskStatus: String, Codable, Sendable, Equatable {
    case pending, running, succeeded, failed, cancelled
}

struct ExportRecord: Codable, Identifiable, Sendable {
    let id: UUID
    let assetIdentifier: String
    let kind: MediaKind
    let status: TaskStatus
    let startedAt: Date
    let finishedAt: Date?
    let errorDescription: String?
}

enum WatermarkError: Error, Sendable, Equatable {
    case accessDenied
    case assetUnavailable(assetIdentifier: String)
    case iCloudDownloadFailed(assetIdentifier: String)   // 可重试、不静默降级
    case unsupportedFormat(String)
    case rawConversionRequiresConsent(String)
    case renderFailed(String)
    case encodeFailed(String)
    case writeFailed(String)
    case cancelled
}

// MARK: - Rendering/WatermarkCompositor.swift（块A）
final class WatermarkCompositor: @unchecked Sendable {
    static let shared = WatermarkCompositor()   // 全局唯一 CIContext(Metal)，批量共享渲染上下文
    private init() {}

    /// 生成水印层位图（应用字色/描边/阴影/不透明度/字间距，PNG 保 alpha），不含 placement 几何。
    /// outputPixelSize 用于字号 pt→px 换算与 scale 基准；同一 config 结果内部缓存，避免逐帧重建。
    func watermarkLayerImage(for content: WatermarkContent,
                             outputPixelSize: CGSize) throws -> CGImage

    /// 将 base 与水印层按 placement（位置/缩放/旋转/平铺/安全区吸附）合成，返回同尺寸 CGImage。
    func composite(base: CGImage,
                   watermark: CGImage,
                   config: WatermarkConfig,
                   outputPixelSize: CGSize) throws -> CGImage

    /// 预览与导出统一入口。seconds 为素材当前时间（视频/Live 视频段）；
    /// nil 或落在 timeRange 外且非全程时返回不带水印的 base（downscale 由调用方决定）。
    /// 照片/GIF 恒传 nil。
    func compositedFrame(base: CGImage,
                         config: WatermarkConfig,
                         outputPixelSize: CGSize,
                         seconds: TimeInterval?) throws -> CGImage
}

// MARK: - PhotoLibrary/PhotoLibraryService.swift（块A）
final class PhotoLibraryService: @unchecked Sendable {
    func requestAccess() async -> PhotoAccessLevel          // full / addOnly / denied
    func fetchAllAssets() async -> [LibraryAsset]            // 混合类型，按创建日期倒序
    func groupByDay(_ assets: [LibraryAsset]) -> [AssetDayGroup]
    func startCaching(_ assets: [LibraryAsset], targetSize: CGSize) // PHCachingImageManager 封装
    func stopCaching()

    /// iCloud 原图数据下载：带进度回调、内部最多重试 3 次，失败抛 iCloudDownloadFailed（不降级缩略图）。
    func originalImageData(for asset: LibraryAsset,
                           progress: @Sendable @escaping (Double) -> Void) async throws -> Data
    /// 视频/Live 视频段：导出为临时文件 URL（AVAssetExportSession passthrough），同上语义。
    func originalVideoURL(for asset: LibraryAsset,
                          progress: @Sendable @escaping (Double) -> Void) async throws -> URL
    /// Live Photo 拆解为 still 数据 + paired MOV URL。
    func livePhotoPair(for asset: LibraryAsset,
                       progress: @Sendable @escaping (Double) -> Void) async throws -> (stillData: Data, stillUTI: String, videoURL: URL)
    /// 原始格式探测：UTI、编码器、位深、色彩空间（EXIF 保留与处理器分流依据）。
    func formatInfo(for asset: LibraryAsset) async throws -> AssetFormatInfo
}

struct AssetFormatInfo: Sendable, Equatable {
    let uti: String                 // 如 "public.heic"
    let bitDepth: Int
    let colorSpaceName: String?
    let codec: String?              // 视频轨 hvc1/avc1 等
}

// MARK: - Processing/AssetProcessor.swift（块B）
protocol AssetProcessor: Sendable {
    var kind: MediaKind { get }
    /// 单素材端到端：取原图 → 逐帧/单帧合成 → 原格式编码。progress 0...1。
    func process(asset: LibraryAsset,
                 config: WatermarkConfig,
                 library: PhotoLibraryService,
                 compositor: WatermarkCompositor,
                 progress: @Sendable @escaping (Double) -> Void) async throws -> ProcessedOutput
}

enum ProcessedOutput: Sendable {
    case stillImage(data: Data, uti: String)                       // 照片：原编码器原样写回（<=256KB 小图）
    case imageFile(url: URL, uti: String)                          // v1.2：大图落 tmp 的等价形态，导出走 fileURL
    case livePhoto(stillData: Data, stillUTI: String, videoURL: URL) // 已重新配对（同 assetIdentifier）
    case animatedImage(data: Data, uti: String)                     // GIF/WebP：帧数/延时/循环/调色板原样
    case video(url: URL)
}

struct PhotoProcessor: AssetProcessor { /* HEIC/HEIF/JPEG/PNG/TIFF/BMP/WebP + RAW→HEIC(需先 rawConsent) */ }
struct LivePhotoProcessor: AssetProcessor { /* still+MOV 分别加水印后重配对 */ }
struct AnimatedImageProcessor: AssetProcessor { /* CGImageSource 逐帧 → CGImageDestination */ }
struct VideoProcessor: AssetProcessor { /* Reader→合成→Writer，音频 passthrough */ }

// MARK: - Processing/BatchQueue.swift（块B）
final class BatchQueue: @unchecked Sendable {
    static func recommendedConcurrency(physicalMemoryBytes: UInt64) -> Int
    // ≤4GB → 3；>4GB → 4（按 ProcessInfo.processInfo.physicalMemory 自适应）

    /// 批处理主入口。失败单任务不阻断；cancel() 只终止未完成任务，已完成保留。
    /// 返回 AsyncStream，UI 逐条消费；任务全部结束后 stream 正常 finish。
    func run(tasks: [LibraryAsset],
             config: WatermarkConfig,
             rawConsent: Bool,
             processorProvider: @Sendable @escaping (MediaKind) -> any AssetProcessor,
             library: PhotoLibraryService,
             compositor: WatermarkCompositor) -> AsyncStream<BatchProgress>

    func cancel()          // 幂等；不回滚已完成任务
    var outputs: [ProcessedOutputBundle] { get }  // 结束后取全部成功产物（含正在排队时完成的）
}

struct BatchProgress: Sendable, Equatable {
    let taskID: UUID
    let assetID: String            // assetIdentifier
    let status: TaskStatus         // running/succeeded/failed/cancelled
    let fractionCompleted: Double  // 单任务 0...1
    let succeededCount: Int
    let failedCount: Int
    let totalCount: Int
    let error: WatermarkError?
}

// MARK: - Export/ExportService.swift（块B）
struct ProcessedOutputBundle: Sendable {
    let assetIdentifier: String
    let output: ProcessedOutput
    let originalCreationDate: Date?
    let originalFilename: String?
    let isRawConverted: Bool        // RAW→HEIC 告知标记
}

final class ExportService: @unchecked Sendable {
    /// 一次 PHPhotoLibrary.performChanges 批量写回：
    /// - photo: PHAssetCreationRequest.addResource(.photo, data/file, options)
    /// - livePhoto: 同一 creationRequest 内 .photo + .pairedVideo 两资源（同 assetIdentifier 已在产物内配对）
    /// - 保留 creationDate / originalFilename（PHAssetResourceCreationOptions）
    /// - RAW 转换过的素材经 onRawConversion 回调逐条告知（文案见 §8）
    /// - albumName 非空则归入「已加水印」相簿（幂等创建）
    /// - addOnly 权限走 PHAssetCreationRequest（仅添加路径同样可用）
    func saveToLibrary(_ bundles: [ProcessedOutputBundle],
                       albumName: String?,
                       onRawConversion: @Sendable @escaping (String) -> Void) async throws -> ExportSummary
}

struct ExportSummary: Sendable, Equatable {
    let records: [ExportRecord]     // 每素材一条，含成败与耗时
}
```

**契约要点**：① `WatermarkPlacement` 归一化坐标一律相对**输出像素**，UI 拖拽层负责 pt↔px 换算；② 预览与导出必须都走 `compositedFrame`，禁止 UI 自绘水印造成两套管线；③ `outputs` 取产物时机 = stream finish 之后。

## 六、性能硬指标实现路径（iPhone 12+ 实测验收）

1. **30×4000×3000 JPEG ≤8s**：① 全局唯一 `CIContext(Metal)`（批量共享渲染上下文，创建开销只付一次）；② 每任务流水线 = CGImageSource 解码 → `compositedFrame` GPU 合成 → CGImageDestination 以**原 UTI** 编码（JPEG `kCGImageDestinationLossyCompressionQuality=1.0`、不缩放），解码/合成/编码三段不落中间副本；③ 同一素材严禁二次解码：原图 Data 与解码 CGImage 在任务内缓存，缩略图用缩略图缓存而非重解码；④ 禁 CPU 逐像素——文字描边/阴影全部经 Core Image 滤镜（CIAttributedTextImageGenerator 不适用时走 CoreText 出层后 GPU 变换）；⑤ 3-4 并发摊满 GPU，每任务 `autoreleasepool` 包裹。
2. **视频硬编与码率**：AVAssetWriterInput `AVVideoCodecKey` 与源一致（hvc1→HEVC Main10、avc1→H.264），profile/level 取 `max(源值, 平台推荐)`；`AVVideoAverageBitRateKey = max(源标称×1.15, 源实际平均码率×1.15, AVVideoRecommended...)`；色彩属性从源 track `formatDescription` 复制 colorPrimary/transferFunction/matrix（HLG→HLG、BT.2020→BT.2020），**禁 tone map**。1min 1080p30 ≤30s、1min 4K30 ≤60s 依赖 VideoToolbox 硬编直通，不做帧率/分辨率任何调整；旋转用 preferredTransform 烘焙进 buffer，不改元数据路径。
3. **音频 passthrough**：`AVAssetReaderTrackOutput(track:, outputSettings: nil)` 输出**压缩** CMSampleBuffer，直接 `writerInput.append(_:)`；writer input `mediaType=.audio` + `sourceFormatHint=track.formatDescription`，不设 outputSettings → 不重编码；音画同步靠 reader/writer 均按时间戳透传，禁 PTS 重写。
4. **4K 内存峰值 <250MB**：帧级 `autoreleasepool` + reader 逐帧拉取（不预读队列堆积）；水印层 CGImage 复用（缓存，见 §4）；输出走 `AVAssetWriterInputPixelBufferAdaptor` 的 `CVPixelBufferPool`；任何路径禁止整段视频载入内存、禁止全帧数组持有。
5. **预览 ≥55fps、点水印 <100ms**：预览基图用降采样 CGImage（≤屏幕 2 倍像素）；水印层生成后缓存，拖动仅重跑 GPU 合成（毫秒级）；AVVideoComposition 的 custom compositor 每帧调 `compositedFrame(seconds:)`，与导出同一函数——**同管线由代码结构保证而非测试保证**。
6. **EXIF 全量保留**：`CGImageSourceCopyPropertiesAtIndex` 整个属性字典（EXIF/TIFF/GPS/MakerApple/色彩空间/位深）原样作为 `CGImageDestinationAddImage` 的 properties 传入，不做键过滤；方向以像素烘焙（pre-bake orientation）后清 orientation 键，避免双重旋转；PNG 恒用无损路径保 alpha。
7. **Live Photo 配对**：拆解 still 与 paired MOV → **各自独立加水印**（still 走照片管线、MOV 走视频管线但保持原时长/分辨率）→ 在 still 的 HEIC 里写 MakerApple 字典 key 17 = assetIdentifier（UUID 格式与系统一致）、在 MOV 写 `com.apple.quicktime.content.identifier` 轨道元数据 = 同一 UUID → `PHAssetCreationRequest` 内 `addResource(.photo…)` + `addResource(.pairedVideo…)` 双资源，系统重建为可播放 Live Photo。
8. **写回**：整批一次 `PHPhotoLibrary.performChanges`：`creationRequest.creationDate = 原创建时间`，`PHAssetResourceCreationOptions.originalFilename = 原文件名`；原图全程只读（仅 PHAssetCreationRequest 新建，不 modify 原资产）。

**非功能性基线（质量测试官据此验收）**：批量页 UI 主线程无卡顿（处理全部后台线程/actor）；崩溃率目标 ≤0.1%（未捕获 Swift 错误全接入 WatermarkError 分支）；权限被拒时功能明确降级提示，不静默失败；本地数据（模板/记录）仅存 Documents+UserDefaults，随 iCloud 备份；无网络权限声明（Info.plist 不含任何 networking usage）。

## 七、BGProcessingTask 后台续跑与 Info.plist

注册 `com.watermarkbatch.export`（BGProcessingTask，`requiresNetworkConnectivity=false`、`requiresExternalPower=false`）；批任务启动时 `BGTaskScheduler.submit`；进入后台由系统唤起后由 `BGTaskCoordinator` 从持久化的待办清单（任务资产 ID + WatermarkConfig 序列化）重建 BatchQueue 续跑；`expirationHandler` 中调用 `batchQueue.cancel()` 并落盘已完成产物与剩余清单。Info.plist 必需键：

| 键 | 值 |
|---|---|
| `NSPhotoLibraryUsageDescription` | "导入照片并批量添加水印" |
| `NSPhotoLibraryAddUsageDescription` | "将加水印后的照片保存回相册" |
| `BGTaskSchedulerPermittedIdentifiers` | `["com.watermarkbatch.export"]` |
| `UIBackgroundModes` | `["processing"]` |
| （不声明任何网络/定位权限） | 纯本地，审核零敏感面 |

注：addOnly 授权下无法用 PHPicker 之外方式读取既有相册——App 需完全访问才能批量导入；addOnly 仅覆盖「仅写入」路径（如从分享面板进入），权限页文案须明示该差异。

## 八、风险与边界

1. **HDR/10bit 视频保真（Top1）**：触发条件 = 导出 HLG/Dolby Vision/BT.2020 4K 素材。风险：合成路径意外引入 tone map 或位深塌陷。预案：VideoWriterConfig 显式复制三色彩属性+Main10 profile；验收方法 = 导出后对同帧做 PSNR/SSIM（PSNR≥42dB、SSIM≥0.98 为门禁，测试工具在 Mac 端用 ffmpeg+iqa 脚本执行）；不达标即回退该文件为「逐项参数告警」而非静默上线。
2. **Live Photo 重配对（Top2）**：触发条件 = iOS 版本更新改变 MakerApple 17 键写入格式或系统拒绝配对。预案：写入后用 `PHLivePhoto.request(withResourceFileURL:)` 自检可播放性；失败时不写库、用户可读错误（绝不产出残缺资产），并在 Mac 验证机覆盖 iOS 17/18 双版本回归。
3. **Windows 环境无法编译（Top3）**：触发条件 = 本方案到 Mac 落地首编译。风险：契约与实现漂移。预案：§4 接口契约即「编译契约」，三个实现块开工前各自建 `.swift` 空壳按签名编译通过再填实现；本文全部代码行标注「需在 Mac+Xcode 16 验证」。
4. **RAW/DNG→HEIC 告知交互**：RAW 无法"原样保留"输出回相册（系统写回 RAW 需 ProRAW 特例且加水印必破坏原始性），方案 = 编辑器首选拖入 RAW 素材时弹窗："RAW 照片将转换为 HEIC 加水印后保存，原 RAW 文件不会修改。是否继续？"；`BatchQueue.run(rawConsent:)` 为显式参数，未同意且含 RAW 时整批拒绝启动；每条 RAW 结果经 `onRawConversion` 二次提示，绝不静默转换。
5. **视频「视觉无损」验收**：以 PSNR≥42dB / SSIM≥0.98 为客观门禁（水印区域除外——对比区域为水印层外像素），辅以逐帧抽查；JPEG 1.0 与音频 passthrough 不设客观指标（格式参数不变即达标）。

**与上游对齐确认**：本方案与用户原始需求逐条对齐（8 大项全部覆盖），无矛盾点；「不做」清单（云端/账号/分享/广告/内购/滤镜/AI）在架构上未留任何入口。
