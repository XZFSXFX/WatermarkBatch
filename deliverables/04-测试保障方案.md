## 二、用例矩阵：原始需求 9 条自测验收清单逐条转化

> 编号规则：AC = 验收清单正例；EX = 异常流（第五章）。所有用例在 Mac + Xcode 16 + 真机执行。

**TC-AC-001｜模块：批量引擎｜标题：100 张混合素材批量加水印全部成功**
- 优先级：P0｜前置：真机相册预置 100 张混合素材（JPEG 30 / HEIC 20 / Live Photo 15 / GIF 10 / 1080p 视频 15 / 4K 视频 10），完全访问权限
- 步骤：1. Tab1 全选 100 张 → 开始编辑；2. 配置文字水印（描边+阴影）；3. 批量套用并导出，二次确认；4. 等待批次完成
- 预期：1. 成功计数=100、失败=0；2. 相册新增 100 个带水印副本，原图均未被修改（对比导入前后 PHAsset modificationDate）；3. UI 全程可切 Tab 不阻塞
- 工具：预置素材脚本（AirDrop 批量导入）+ XCTest 断言 modificationDate

**TC-AC-002｜模块：照片导出｜标题：JPEG 像素尺寸/EXIF/方向与原文件完全一致**
- 优先级：P0｜前置：含 EXIF（GPS/镜头/拍摄时间）与 90°/270° 方向标记的 JPEG 各 5 张
- 步骤：1. 单张加水印导出；2. Mac 端 `exiftool` 比对原/新文件；3. 比对像素尺寸与视觉方向
- 预期：尺寸逐像素一致（零缩放）；EXIF 关键字段（DateTimeOriginal/GPS/LensModel/Orientation 烘焙后视觉方向一致）；JPEG 质量=1.0（默认画质优先档；「优先速度」档为 0.95，属弹窗明示的降级，单测覆盖两档）
- 工具：`exiftool -a -G1 original.jpg marked.jpg` diff 脚本 + 单元测试 EXIFPreserver 字典 diff

**TC-AC-003｜模块：Live Photo｜标题：输出后长按可播放且两段水印位置一致**
- 优先级：P0（用户红线，PRD F-19）｜前置：iPhone 拍摄的 Live Photo 20 个（iOS 17 与 iOS 18 各拍 10 个）
- 步骤：1. 加水印批量导出；2. 相册中逐个长按检查播放；3. 导出后调用 `PHLivePhoto.request` 自检 + 抽帧比对静帧与视频段水印位置
- 预期：20/20 长按可播放；配对成功率 100%；静帧与动段水印位置视觉一致（同一 placement 换算基准）
- 工具：XCTest 集成用例（PHLivePhoto 自检）+ iOS 17/18 双版本回归库

**TC-AC-004｜模块：动图导出｜标题：GIF 帧数/每帧延时/循环次数与原文件相同**
- 优先级：P1｜前置：GIF 10 个（含透明背景 3 个、>150 帧长 GIF 2 个）
- 步骤：1. 加水印导出；2. Mac 端用 `ffprobe`/ImageMagick `identify` 比对原/新文件
- 预期：帧数一致、每帧 delay 一致、循环次数（NETSCAPE2.0）一致、透明区域逐帧保留、导出后仍为动图
- 工具：`identify -format "%T %n\n" x.gif` 比对脚本

**TC-AC-005｜模块：视频导出｜标题：4K HDR 输出色彩不变灰、音频无重编码、无块效应**
- 优先级：P0｜前置：iPhone 拍摄 HLG 4K30、Dolby Vision 4K30 各 2 条（含音频）
- 步骤：1. 加水印导出；2. Mac 端 `ffprobe` 核对色彩标签（color_primaries/transfer/matrix）与编码器；3. PSNR/SSIM 比对（方法见 §4.4）；4. 音频流 `streamcopy` 校验（比对原/新音频 md5）；5. 目视 100% 放大查块效应；6. `ffprobe` 比对输出码率 vs 码率公式（双档各测）
- 预期：色彩标签与原一致（不变灰=未 tone map）；音频 md5 一致（passthrough 未重编码）；PSNR≥42dB / SSIM≥0.98（水印区域外）；视频码率 = max(原码率 × 系数, 平台推荐值)——**默认画质优先档系数 ×1.3，「优先速度」档系数 ×1.0**（技术方案 v1.1 口径）
- 工具：ffmpeg/ffprobe + PSNR/SSIM 脚本（§4.4）

**TC-AC-006｜模块：预览一致性｜标题：预览水印位置与导出结果像素级一致（误差≤1pt）**
- 优先级：P0｜前置：4000×3000 照片、4K 视频各 1；水印置于非对称位置（旋转 37°）
- 步骤：1. 预览截图；2. 导出后取同参数产物帧；3. 脚本计算水印层左上/右下角坐标差
- 预期：两图水印角点坐标差 ≤ 输出像素 1pt 换算值（同管线 `compositedFrame` 保证）；截图比对脚本自动判定
- 工具：Python PIL 角点匹配脚本（预览截图 vs 导出帧）

**TC-AC-007｜模块：任务韧性｜标题：断网/锁屏/切后台/低电量模式批量任务不崩不丢**
- 优先级：P0｜前置：50 张批量任务运行中；分四轮执行（每轮一因素）
- 步骤：轮1 断网（iCloud 素材下载中）；轮2 立即锁屏 5 分钟；轮3 切后台 3 分钟再回前台；轮4 开启低电量模式跑全批
- 预期：四轮均无崩溃；已完成结果全部落盘可见；回前台进度延续或按 PRD 4.2 提示继续/放弃；低电量模式下批次完整跑完（仅耗时允许上升）
- 工具：Xcode Organizer/MetricKit 崩溃监控 + `xcrun simctl` 不适用（必须真机）

**TC-AC-008｜模块：权限｜标题：拒绝相册权限给出可操作引导、不闪退**
- 优先级：P0｜前置：首次安装，系统相册权限选择「拒绝」；另一轮选「仅添加照片」
- 步骤：1. 拒绝权限后冷启动；2. 检查引导卡片与「打开设置」跳转；3. 跳系统设置改为完全访问后返回 App；4. 另一轮以「仅添加」权限进入（v1.0 预期明示：读取需完全访问，写入路径可用）

## 四、性能实测方法（Mac + Xcode 16 + iPhone 12 真机）

### 4.1 工具组合
- **Instruments**：Time Profiler（8s 批量主线程与热点函数）、Allocations（内存峰值，All Heap & Anonymous VM）、Core Animation FPS（预览拖动帧率）、Energy Log（耗电）。
- **MetricKit**：生产/验收双通道接收 `MXDiagnosticPayload`（崩溃/hang）与 `MXMetricPayload`（内存、耗电、启动），批量结果页埋点 `task_result` 记录逐素材耗时与内存峰值，作为验收数据源。
- **XCTest benchmark**：六项指标固化为 `measure {}` 用例 + 自定义 JSON 输出，接入 Xcode Cloud/GitHub Actions CI，每次构建在基准机以「优先速度」档跑一轮冒烟（30 张 8s 项 + 内存项），失败阻断发布。

### 4.2 逐项测量步骤与判定（双口径：默认画质优先档 / 「优先速度」档）

> 两档各测一轮（每项 5 轮取中位数）。「优先速度」档达标 = 发布门禁；默认档按预期区间验收，**实测达不到就如实记录实测值，禁止改目标值「达标」**（v1.1 裁决口径）。

| 指标 | 测量步骤 | 判定 |
|------|----------|------|
| 30×4000×3000 JPEG | 点「批量导出」至批次完成回调计时（XCTest `CFAbsoluteTimeGetCurrent`），5 轮取中位数；Time Profiler 确认无 CPU 逐像素路径 | 速度档 ≤8.0s（门禁）；默认档预期 10-12s（如实实测入报告） |
| 1min 1080p30 / 1min 4K30 | 同上计时；记录 GPU/硬编占用 | 速度档分别 ≤30s / ≤60s（门禁）；默认档预期 1080p30 30-40s、4K30 60-80s（如实实测入报告） |
| 4K 内存峰值 | Allocations 标记批处理起点/终点，取区间峰值（含 Anonymous VM）；SE 机复测 | 速度档 <250MB（门禁）；默认档目标 <200MB，超限应降并发不降画质（复测确认画质不受影响） |
| 预览拖动 | Core Animation instrument + `CADisplayLink` 打点（编辑器内嵌调试计数器），连续拖拽 30s 记录帧间隔分布 | 两档一致：P55 帧率 ≥55fps（即 95% 帧时长 ≤18.2ms；预览帧率与批量并发档无关） |
| 点水印到画面 | 参数变更时间戳 → 首帧合成完成回调打点，50 次取 P95 | 两档一致：P95 <100ms |
| 冷启动 | MetricKit MXAppLaunchMetric + 手工秒表复核 | ≤3s |

### 4.3 弱网测试
iPhone 12 + Mac「网络连接共享」限速工具模拟 3G/断网；仅作用于 iCloud 原图下载场景（App 本身零网络请求）。

### 4.4 PSNR/SSIM 视觉无损验证（Mac 终端）

**抽帧比对（逐帧全局指标，取逐帧最小值判定）**：
```bash
# 1. 对齐抽帧：源与导出文件各抽 1fps 共 60 帧
ffmpeg -i source.MOV -vf fps=1 src_%03d.png
ffmpeg -i marked.MOV -vf fps=1 out_%03d.png
# 2. PSNR（逐帧，取每帧报告值的最小值）
ffmpeg -i src_%03d.png -i out_%03d.png -lavfi "psnr" -f null - 2>&1 | grep psnr
# 3. SSIM
ffmpeg -i src_%03d.png -i out_%03d.png -lavfi "ssim" -f null - 2>&1 | grep SSIM
```
**水印区域遮蔽比对（门禁口径：水印层外像素比对）**——用 PyAV/NumPy 脚本：预览页已知水印包围盒 → 将两帧同区域置灰/裁除后再计算 PSNR/SSIM：
```bash
# 快速法：crop 掉水印包围盒后全片比对（水印固定于右下角示例）
ffmpeg -i marked.MOV -i source.MOV -filter_complex \
"[0:v]crop=iw-400:ih-300:0:0[a];[1:v]crop=iw-400:ih-300:0:0[b];\
[a][b]psnr" -f null -
```
**判定**：非水印区域逐帧 PSNR≥42dB 且 SSIM≥0.98（取最小帧值，不用均值掩盖坏帧）；HDR 样本另用 `zscale` 转线性域后复核一次防 tone map 漏检（变灰可直接从 `ffprobe` 的 color_transfer 标签判死刑）。
**音频 passthrough 校验**：`ffmpeg -i x.mov -map 0:a -c copy a.m4a` 对原/新音频分别提取后 `md5` 一致。

## 五、边界与异常用例（异常流 ≥ 正常流一半，实测 12 条 ≥ 9/2）

**TC-EX-001｜iCloud 下载中断重试**（P0）：iCloud 未下载素材 ×10 开启下载 → 中途飞行模式 → 预期：进度暂停+「网络不可用」提示，恢复网络自动续传或手动重试；连续 3 次失败进失败清单，**绝不静默用缩略图处理**（导出文件尺寸必须等于原图）。
**TC-EX-002｜存储空间不足**（P0）：剩余空间 < 单批预计产物 2 倍时启动批量 → 预期：写入前预估检查并给出可读错误（清理引导），已导出部分保留，无半写残片。
**TC-EX-003｜中途取消**（P0）：100 张跑到第 40 张点取消 → 预期：确认弹窗明示「已完成 X 张保留」；已完成 40 张在相册与记录可见；未处理项状态=cancelled 不算失败。
**TC-EX-004｜后台回收后续跑**（P1）：批量中切后台被系统挂起/杀进程 → 重启 App → 预期：待办清单重建续跑（BGTaskCoordinator 落盘恢复），无重复写入、无丢结果。
**TC-EX-005｜仅添加权限写路径**（P0）：仅添加权限下走写入路径（分享面板进入）→ 预期：写入成功；读取路径明示需完全访问，无崩溃无静默失败。
**TC-EX-006｜单任务失败不阻断**（P0）：100 张中注入 1 个损坏/不支持文件 → 预期：其余 99 张完成，失败项给出具体原因（WatermarkError 文案），可一键重试失败项。
**TC-EX-007｜RAW 混批告知**（P1）：含 RAW/DNG 批次 → 预期：导出前弹窗（文案与 PRD 7.2 逐字一致），不同意则整批拒绝启动，绝不静默转 HEIC。
**TC-EX-008｜空数据态**（P2）：空相册/空模板/空记录 → 预期：插画+引导文案，无白屏。
**TC-EX-009｜数值输入非法值**（P1）：X/Y 输入负数/超大值、缩放 0%、旋转 999° → 预期：红框提示并保留上次合法值。
**TC-EX-010｜锁屏中断 + 回前台**（P0，v1.0 口径）：批量中锁屏 → 预期：回前台提示「继续/放弃」，状态一致不串批。
**TC-EX-011｜超长 GIF 内存**（P1）：200 帧 GIF ×5 连续满队列处理（「优先速度」档并发上限压测）→ 预期：流式逐帧不 OOM，无 Jetsam 杀进程。
**TC-EX-012｜来电中断**（P1）：视频预览/批量中来电话 → 预期：接挂后状态恢复，任务不中断不重复。

**Bug 报告规范**（缺项无效）：标题 `[模块] 现象+条件`；环境（机型/系统/构建号/权限态/电量）；编号复现步骤；实际 vs 预期分开写；证据（截图/录屏/sysdiagnose/MetricKit 诊断）；复现概率（必现/高频/偶现注明次数比）。格式降级类缺陷（缩图、EXIF 丢失、Live 失活、HDR 变灰、音频重编码）**自动升 P0**。
